## 구현 내용

- 80개 고해상도 원본은 `source-assets/chords`에 보존하고, Sharp 스크립트가 720px 폴백 PNG·720px 무손실 WebP·240px WebP 썸네일을 결정적으로 생성한다.
- 모든 래스터 다이어그램은 `<picture>`의 WebP 우선/원본 폴백, 고유 `width`/`height`, 지연 로딩과 비동기 디코딩을 사용한다. 현재 경로의 첫 의미 있는 갤러리 카드만 `fetchpriority="high"`로 요청한다.
- 첫 화면 이미지 경로는 해시 라우트를 기준으로 조기에 선로드하며, 다른 화면에서 보이지 않는 이미지는 선로드하지 않는다.
- 퀴즈·설정 패널·인쇄·수업 세트·홈 선택 화면·PWA 업데이트 UI를 `React.lazy`/`Suspense` 경계로 분리했다. 수업 도구와 홈 화면 CSS도 해당 청크와 함께 지연 로드한다.
- React/Supabase/DnD/QR을 수동 vendor 청크로 분리했다. HTML에서 시작되는 초기 JS는 gzip 93,907B이다.
- Pretendard 1.3.9를 OFL에 맞춘 자체 패밀리명으로 제공하고, 앱 핵심 글리프 72,788B + KS X 1001 보충 369,100B WOFF2로 분리했다. 둘 다 `font-display: swap`을 사용한다.
- `ChordCard`와 그리드 셀을 메모화하고 즐겨찾기 콜백 참조를 안정화했다. 검색 디바운스는 120ms이다.
- 갤러리의 손가락 힌트는 포인터 진입 시 즉시, 아니면 초기 렌더 뒤 400ms에 마운트해 기존 상호작용을 보존하면서 첫 페인트의 DOM 작업을 줄였다.
- 스크롤 가상화는 사용하지 않았다. 초기 카드 한 개를 먼저 그린 뒤 전체 소규모 목록을 두 프레임 안에 마운트한다.
- 이미지 검사는 80개 원본/폴백/상세 WebP/썸네일 WebP의 수·경로·실제 치수·알파·픽셀 유사도와 런타임 메타데이터를 교차 검증한다.

## 화질 검증

80개 전체를 원본/폴백/상세/썸네일 접촉 시트와 확대 보기로 비교했다. 누락, 잘림, 코드 오매칭, 문자·선 손상, 알파 손상은 없었다. 상세 WebP 평균 MAE 0.612/PSNR 38.9dB, 썸네일 평균 MAE 1.165/PSNR 36.94dB였으며 240px 실제 표시 크기에서 육안 열화가 확인되지 않았다.

## 자동 예산

`npm run check:performance`는 다음을 빌드 산출물에서 강제한다.

- `dist` < 3,000,000B
- 코드 에셋 < 1,800,000B
- 개별 JS 청크 < 500,000B
- HTML 시드 초기 JS gzip < 120,000B
- core/supplement WOFF2 합계 ≤ 450,000B
- 지연 vendor 및 화면 CSS가 초기 HTML에 포함되지 않음

Windows의 Lighthouse CLI가 JSON 보고서를 정상 기록한 뒤 임시 프로필을 지우는 과정에서 `EPERM`을 반환하는 환경 이슈가 있었으며, 위 수치는 완성된 JSON 보고서의 감사 결과를 직접 집계했다.
